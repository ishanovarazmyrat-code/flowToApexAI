# Patterns that MUST trigger NOT_TRANSLATABLE
- try / catch blocks (Flow has no exception handling)
- Dynamic SOQL (Database.query, dynamic field name string concatenation)
- @future, Queueable, Schedulable, Batchable, Finalizer
- Recursive method calls (a method calling itself directly or transitively)
- HTTP callouts (HttpRequest, Http.send, Callout:NamedCred)
- Custom exception classes (extends Exception)
- Anonymous inner classes
- Complex string parsing / regex business logic (split + parse + reconstruct)
- Map<KeyType, ValueType> where KeyType is NOT Id and the map is used as a lookup table
  (true map semantics — Flow has no associative array)
- Set<KeyType> where KeyType is NOT Id and used for de-duplication of non-record values
- Multiple SObject types DML'd inside the same logical branch
  (Flow's Create/Update/Delete elements are single-object scoped)
- Nested loops sharing mutable counters or aggregators across iterations
- SOSL (FIND ... RETURNING)
- Schema describe calls (Schema.getGlobalDescribe, getDescribe, getPicklistValues)
- Asynchronous patterns (System.enqueueJob, System.schedule)

# Patterns that ARE translatable — do NOT refuse for these
- A single Map<Id, SObject> used purely as a transient bulk-DML collector
  (loop populates the map, single update outside the loop) — this is the canonical
  bulk pattern from the Flow-to-Apex converter and round-trips cleanly to a Flow
  with a Loop + Update Records element.
- Set<Id> used to gather IDs for a SOQL WHERE Id IN :ids — maps to a Flow
  collection variable feeding a Get Records element.
- if / else if / else chains of any depth (map to Flow Decisions, one outcome per branch).
- for-each loops over an SObject collection returned by SOQL (Get Records → Loop).
- record.FieldName = value assignments inside the main records loop (per-record context).
- oldMap.get(record.Id).FieldName comparisons (map to $Record__Prior).

# Object detection
Handlers generated by this system implement IFlowMigrationHandler and use this signature:

    public void run(System.TriggerOperation op, List<SObject> records, Map<Id, SObject> oldMap)

The trigger object is determined by the cast inside the method body:

    for (SObject sObj : records) {
        <Object> record = (<Object>) sObj;   // ← the cast type IS the trigger object
        ...
    }

Look for the first cast of `sObj` to a concrete SObject type (e.g. `Account record = (Account) sObj;`).
That concrete type is the trigger object for the Flow.

If the handler does not match this signature, refuse with reason:
  "Apex handler does not match the expected IFlowMigrationHandler.run(op, List<SObject>, Map<Id,SObject>) signature."

# Operation detection (Apex op-gate -> Flow triggerType + recordTriggerType)
Inspect the early-return / op-equality checks at the top of run() and map them to Flow attributes:

  if (op != BEFORE_INSERT) return;
    -> triggerType=RecordBeforeSave, recordTriggerType=Create

  if (op != BEFORE_UPDATE) return;
    -> triggerType=RecordBeforeSave, recordTriggerType=Update

  if (op != BEFORE_INSERT && op != BEFORE_UPDATE) return;  (or equivalent)
    -> triggerType=RecordBeforeSave, recordTriggerType=CreateAndUpdate

  if (op != AFTER_INSERT) return;
    -> triggerType=RecordAfterSave, recordTriggerType=Create

  if (op != AFTER_UPDATE) return;
    -> triggerType=RecordAfterSave, recordTriggerType=Update

  if (op != AFTER_INSERT && op != AFTER_UPDATE) return;  (or equivalent)
    -> triggerType=RecordAfterSave, recordTriggerType=CreateAndUpdate

If the gate handles a mix that does not collapse to one of the six cases above (e.g.
BEFORE_INSERT + AFTER_UPDATE), refuse with reason:
  "Apex op-gate mixes before-save and after-save operations; Flow allows only one trigger timing."

# Translation rules — Apex element -> Flow element
- The handler's main `for (SObject sObj : records)` loop is NOT a Flow Loop element.
  It is the per-record context — translate its body directly to Flow elements that
  operate on $Record. Use $Record.FieldName for record.FieldName (where record was cast from sObj).
- A `for (SObject sObj : someCollection)` or `for (X item : someCollection)` INSIDE the
  main loop IS a Flow Loop element, iterating someCollection (typically a Get Records output).
- record.FieldName = value           -> Assignment element writing to $Record.FieldName
- if / else if / else                -> Decision element with one Outcome per branch
- List<X> xs = [SELECT ... FROM X ...] -> Get Records (recordLookups) element
- insert <ref>                       -> Create Records (recordCreates) element
- update <ref>                       -> Update Records (recordUpdates) element
- delete <ref>                       -> Delete Records (recordDeletes) element
- (<Object>) oldMap.get(record.Id)   -> $Record__Prior

# Reference translation
- sObj / record (after cast)         -> $Record
- record.FieldName                   -> $Record.FieldName
- (<Object>) oldMap.get(record.Id)   -> $Record__Prior
- loop iterator variable             -> the Flow Loop element's loop variable

Each non-start element follows this shape (vary the wrapper tag — `decisions`, `assignments`, `recordLookups`, `recordCreates`, `recordUpdates`, `recordDeletes`, `loops`):

    <assignments>
        <name>SetFieldDefault</name>
        <label>Set Field Default</label>
        <locationX>200</locationX>
        <locationY>200</locationY>
        <assignmentItems>
            <assignToReference>$Record.FieldName</assignToReference>

            </value>
        </assignmentItems>
        <connector>
            <targetReference><nextElementName></targetReference>
        </connector>

Decisions use `<rules>` with `<conditions>`, `<connector>` to outcome target, and a `<defaultConnector>` for the else branch.
